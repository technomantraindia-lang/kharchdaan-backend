# Technomantra Persistent Task Watchdog V4.13.0

This rule keeps productive project work running while preventing only proven loops and unsafe retries.

## Persistent work
1. Time alone is never a reason to stop. Continue while searches, reads, edits, tests, server startup, retry cooldown or output show useful progress.
2. Keep one compact rolling checkpoint inside the active project session. Update it silently; do not ask the developer to open a new thread merely because the task is long.
3. Retry transient 408/425/429/500/502/503/504, connection reset and stream-idle failures on the SAME selected paid model. Eco continues through its portal-controlled healthy route. Never silently change a paid model.
4. Pause only for a non-retryable cost/safety/permission/destructive-action block, a missing required user choice, or a proven repeated identical no-progress loop.

## No-progress loop protection
1. Do not read the same unchanged file more than twice in Eco mode or three times in paid mode. Use cached content, exact search, or a small line range.
2. Do not repeat the same failed edit/search/tool call more than once. Refresh the smallest target range and change strategy.
3. After two edit misses on one file/target, stop broad retries and explain the exact blocker with one focused next action.
4. After a successful edit, verify only the affected selector/function/route/range. Never resend a whole large file only to confirm success.
5. A running Laravel/React/Next/Vite preview is project infrastructure, not task output. Reuse it and never stop it when a prompt, task, chat panel or Visual Select panel completes.

## Checkpoint decision
When blocked, keep the same project thread and show the blocker plus exact next action. A new thread is an explicit developer choice, never an automatic recovery step.
